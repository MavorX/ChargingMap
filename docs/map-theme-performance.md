# 地图明暗主题切换

## 原因与处理

旧实现每次切换主题都会调用高德 `setMapStyle`，重新请求样式及地图瓦片。一次线上观测中，样式请求约 3.9 秒，随后瓦片请求约 4.3 秒；界面已经切换，底图仍在等待网络。

现在始终复用同一个地图实例及 `amap://styles/dark` 底图：夜间保留原生深色底图，白天仅在 `MapView.vue` 的底图画布上进行本地明暗合成。切换不调用地图样式接口、不加载另一张隐藏地图、不重建标记，也不改变中心、缩放、选中站点或已有路线。

滤色只匹配 `#map-container` 内 `.amap-layers > canvas.amap-layer`，不应用到整个地图容器。因此 DOM 标记、信息窗口、控件及高德版权不会被反色。没有延迟或主题过渡动画；地图背景同步覆盖 SDK 写入的背景色，避免加载空隙与当前主题不一致。

## 验证范围（2026-10-28）

- 单元回归覆盖初始白天/夜间、SDK 尚在加载时切换、连续切换、保存偏好恢复及存储不可用。
- 检查主题切换不会重建地图、刷新全量标记、重写地图视野或清除路线与选中站点。
- Edge 无头浏览器验证 1440×900 与 390×844 两种视口，连续切换、阻断远程样式/瓦片服务后切换及刷新恢复夜间偏好。
- 实际 SDK 的画布、标记节点、相机及测试折线保留，主题切换新增样式/瓦片请求为 0，无页面异常。
- 使用点击后两帧的观察检查响应，而非只检查 DOM 主题 class 是否改变；实际耗时仍受设备渲染性能影响。窄屏模拟不替代真实手机验收，测试折线也不代表重新验收驾车规划服务。

后续升级地图 SDK 或底图渲染结构时，应重新检查画布选择器、地图文字和路线的可读性，以及主题切换期间的网络请求；不要恢复逐次 `setMapStyle` 来同步主题。
